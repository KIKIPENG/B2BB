# 背面調查局｜展場雙系統網頁

同一個螢幕、左右 7:3 分割：

- **左 70%｜場景描述系統**：10 張場景照片，選一張後對麥克風口述（猜想、位置、事件）→ 逐字稿 → AI 整理成描述 → 歸檔 → 取得「另一位觀眾的描述」。
- **右 30%｜條碼心理測驗**：掃描記錄表上的題目條碼 → 按數字鍵 1–5 評分 → 10 題完成後產生四極雷達圖與類型描述。

純靜態網頁（無需建置）。直接用瀏覽器開 `index.html`，或 `python3 -m http.server`。展場建議 Chrome kiosk：`chrome --kiosk index.html`。

## 操作

| 動作 | 輸入 |
|---|---|
| 掃描題目 | 掃描器（鍵盤模擬，輸出 `Q01`–`Q10` + Enter） |
| 評分 | 數字鍵 1–5 |
| 產生分析 | Enter（10 題完成後） |
| 重新開始 | 0 或 Esc；閒置 120 秒自動重置 |
| 場景描述 | 畫面按鈕：開始說話／重錄／整理成描述／歸檔 |
| 列印結果單 | P（左側已歸檔、右側已分析才可列印） |

掃描時若游標在左側文字框，掃進去的字會自動還原，不會污染描述。

## 檔案

- `js/config.js`：**題目、四極歸屬、類型文案、場景清單、逾時設定**，改文案只改這個檔。
- `js/scoring.js`：計分與類型判定（純函式，可用 node 測試）。
- `js/radar.js`：SVG 雷達圖（上物件、右空間、下事件、左人物）。
- `js/scene.js`：場景描述系統，資料存 `localStorage`（`b2bb.records.v1`）。
- `js/test.js`：條碼測驗狀態機，結果存 `b2bb.results.v1`。
- `js/app.js`：鍵盤輸入分流（掃描器 vs 一般輸入）。
- `assets/scenes/scn_01.jpg … scn_09.jpg`：場景照片，放入後自動顯示（缺圖顯示佔位圖）。

目前的視覺是依 Figma 舊 prototype 做的功能版骨架，待新設計稿定案後替換 `css/style.css` 與版面。

## 設計稿對照用的兩種畫面

- `index.html`（或 `?state=empty`）：全空狀態
- `?state=filled`：所有動作都做完的填滿狀態（示範資料，不寫入觀眾紀錄）
- `?state=sheet`：點陣印表機列印單預覽

## 語音與 AI（需要決定）

- 語音辨識目前用瀏覽器內建 Web Speech API（Chrome，需要網路與麥克風權限，`lang=zh-TW`）。不支援時可直接在逐字稿框打字。
- AI 整理：`js/config.js` 的 `ai.endpoint` 為空時是「離線模式」（只做簡單斷句，不是真 AI）。要接真正的模型，需要自己的後端（不要把 API 金鑰寫在靜態網頁裡），後端收 `POST {scene, transcript}`，回傳 `{guess, location, story, summary}`。
- 「另一位觀眾的描述」：取同一張照片中、其他觀眾最近一筆歸檔紀錄；沒有時用 `seedDescriptions` 的範例（目前只有 SCN_01，且是範例文字）。
- 列印：`P` 鍵呼叫瀏覽器列印，版面依 `config.print`（目前暫設 241×140 mm，待確認中一刀的實際尺寸與印表機驅動設定）。
